# ClinPaper 产品 Demo

## 综述正文阶段 Demo（2026-10-13）

打开以下地址进入对应页面：

- 文献证据与任务输入：`http://localhost:5190/?view=review&stage=evidence`
- 逐章生成、全文整合与投稿前检查：`http://localhost:5190/?view=review&stage=writing`

正文阶段包含三个真实模型任务：

1. `review_section_draft`：按确认大纲顺序逐章生成 Markdown 正文；
2. `review_merge_manuscript`：所有章节成功后自动整合完整正文；
3. `review_preflight`：用户点击“全文检查”后执行投稿前检查。

这三个任务统一通过 `/api/ai` 接收 `promptTemplate` 和结构化 `inputs`，由服务端替换占位符。与早期步骤不同，正文阶段不使用演示回退；模型未配置、网络失败、超时或输出无法解析时会显示失败状态并允许重试。

“查看任务输入”支持按章节编辑 7 项 JSON。覆盖值、章节结果、整合稿、检查结果和忽略状态保存在当前浏览器的 `IndexedDB`，以避免长正文超出 `localStorage` 配额；刷新后可恢复。“任务设置”中的三套提示词作为浏览器全局配置单独保存在 `localStorage`，修改后只影响下一次执行。

全文整合会校验引用标记，阻止新增、删除或重排引用编号。本期不提供科研配图入口，仅保留章节、表格、引用和检查结果等后续配图规划所需结构。

## 启动

```bash
npm install
npm start
```

默认访问地址：`http://127.0.0.1:5190`

## 医学综述：明确需求与方向

首页选择“医学综述”，输入“脊柱结核”等主题并点击“开始写作”，可进入“明确需求与方向”合并工作页。前端作为一个连续任务呈现，后台数据顺序仍为“写作需求 → 候选研究方向”。

当前 Demo 支持：

- 查看研究对象或疾病、主题或方向、重点关注、核心问题和补充写作要求；
- 修改已识别信息，单选主题或方向，多选重点关注，并填写自定义内容；
- 保存需求后更新未选择的系统候选研究方向，并保留已选结果供用户复核；
- 在中间主区域统一比较和选择 1～2 个研究方向，已选卡片原位高亮，不在不同区域之间移动；
- 方向卡片使用一句话说明和“重点判断”标签支持快速比较；详情抽屉将推荐理由转换为“判断维度 + 判断内容”的陈述式结构、将查找重点呈现为短要点，并默认收起问句形式的待验证内容和完整关键词；
- 重新生成只替换未选择的系统候选，不影响已选方向和未选择的自定义方向；
- 通过右侧抽屉填写方向名称、方向说明和选填的查找重点，新增自定义方向；
- 从右侧抽屉查看查找重点、待验证内容和关键词；
- 确认所选方向并进入查找选题文献的后续语义。

## 病例报告：准备正文文献（独立演示页）

首页选择“病例报告”并输入任意演示内容后点击“开始写作”，进入病例报告第 7 步“准备正文文献”。该页面独立于综述和病例汇报 PPT 流程，使用脱敏演示文献展示：

- 只读呈现来自已确认大纲的当前章节与写作重点；
- 按章节切换候选文献，不重新生成证据需求；
- 使用“文献、适用性、支持内容、使用决策”四类核心字段；
- 点击文献打开详情抽屉，查看判断依据、依据范围、使用提醒和病例事实边界；
- 支持“AI 建议使用、待人工核对、已确认用于正文、不使用”四种演示状态；
- 保留病例事实与外部文献的边界提示。

该页面只用于展示病例报告第 7 步的交互方案，不代表其他病例报告步骤已经在 Demo 中实现，也不覆盖综述和 PPT 页面。

## 模型接入

服务端优先读取以下环境变量：

- `MODEL_API_KEY`、`MODEL_BASE_URL`、`MODEL_NAME`：优先复用 ClinPaper 综述的 OpenAI 兼容 `POST /chat/completions` 配置；
- `MODEL_TIMEOUT_MS`、`MODEL_MAX_TOKENS`：可选，与综述模型调用参数保持一致；当前病例汇报长 JSON 页面规划使用 240 秒超时窗口；
- `OPENAI_API_KEY`：配置后启用真实模型生成；
- `OPENAI_BASE_URL`：可选，用于连接兼容 OpenAI Responses API 的自定义模型端点；
- `OPENAI_MODEL`：可选，默认 `gpt-5.4`；
- `PORT`：可选，默认 `5190`。
- `CLINPAPER_DEMO_MODE=1`：强制使用演示回退，便于无费用联调。

`MODEL_API_KEY` 和 `OPENAI_API_KEY` 均未配置时，页面使用脱敏演示数据，并在生成结果旁显示“演示模式”。API Key 不会发送到浏览器。

## 访问地址与任务恢复

- 统一使用 `http://localhost:5190` 打开 Demo；非 API 的 `127.0.0.1:5190` 页面请求会跳转到 `localhost:5190`。
- 当前页面和通用 Demo 状态使用 `localStorage`；综述正文阶段的分章结果、整合稿和检查结果使用 `IndexedDB`，刷新后恢复到原工作区。
- 综述深层链接使用 `?view=review&stage=<stage>`；病例报告正文文献演示页使用 `?view=case-report-evidence`。
- 历史测试地址 `?fix=case-report-start-3` 会自动转换为病例报告正文文献演示页。

模型用于病例结构化、诊疗时间线、汇报主线、大纲、医学依据需求、PPT 页面规划、单页视觉结构重新分析和真实 Layout/槽位选择。所有病例事实均要求来自用户输入；医学依据不得替代病例事实。

## 独立查文献

综合首页的“查文献”入口已通过“按主题查找 / 找特定文献”两个 Tab 区分主题检索和特定文献查找。“找特定文献”使用一个统一输入框，默认文案说明支持 PMID、DOI、期刊、标题和作者；结果页显示系统识别出的单一查询维度。

数据按以下顺序流转：

1. 用户通过 Tab 明确选择主题检索或特定文献查找。“找特定文献”提交后由规则优先识别 PMID、DOI，再由受约束模型或文本规则在期刊、标题、作者中确定一个维度；最终查询计划只保留该维度，不叠加其他字段。
2. 主题检索继续使用 `literature_search_plan → /api/literature/search → literature_batch_analysis`：PubMed 返回真实题录，模型只分析当前返回批次。
3. 特定文献查找使用 `/api/literature/specific-search`，当前 Demo 查询 PubMed、Crossref 和少量已核对的中华医学期刊网 Demo 记录。PMID、DOI 用于精确查询；期刊、标题、作者返回当前维度下的匹配记录。
4. PMID、DOI 精确匹配时自动确认；期刊、作者和部分标题结果作为候选，由用户确认目标文献。年份、卷期和页码只作为返回题录展示，不属于入口维度，也不与当前输入叠加查询。
5. 同一文献优先按 DOI、PMID 等稳定标识合并多来源记录，并保留另一来源补充的 PMID、摘要和页码。所有前端记录使用通用 `recordKey`，不再把 PMID 当作唯一前端主键。
6. 筛选、排序、详情、选择和导出共同使用前端的同一批 `literature.records`；搜索记录在 `localStorage` 中保存检索类型、线索、结果状态、确认目标和记录快照。

主题结果页保留筛选、排序、全选、批量导出和批次分析；特定文献结果页使用单篇确认语义，不显示全选和用户排序，确认目标前导出按钮保持禁用。

PubMed、Crossref 和页面明确标注的中华医学期刊网 Demo 记录是当前 Demo 的题录事实来源。模型不生成或修改 PMID、DOI、题名、期刊和摘要；中文文献没有 PMID 时按正常元数据缺失处理，可使用 DOI 或来源记录标识继续确认。PubMed 未提供 IF、JCR 时页面显示缺失状态并禁用对应筛选，不推测或补造。CSV 使用 UTF-8 BOM，只导出用户当前选择的文献，并包含作者、卷期页码、PMID、DOI、数据来源和来源记录 ID。

中华医学期刊网记录仅用于演示已核对的有限题录，不代表 Demo 已接入或覆盖完整中华医学期刊数据库。线上使用前仍需确认数据授权、查询接口、覆盖范围和元数据冲突规则。

未配置模型时，查文献意图识别、主题规划和批次分析使用受约束的演示回退；PubMed、Crossref 查询仍调用真实接口，失败时保留数据源失败状态，不以模型生成题录替代。

## 单篇文献解读

“查文献”结果页支持对一篇含摘要的文献发起单篇解读。完整流程为：

1. 在文献详情点击“解读文献”，或只选择一篇文献后使用结果页底部入口；
2. 确认报告标题、使用目的、解读详略、输出语言和选填的重点问题；
3. 创建写作任务并调用 `literature_single_interpretation` 模型生成八个固定章节；
4. 在 ClinPaper 统一工作区中编辑正文，并通过既有右侧抽屉逐节核对文献依据；正文页同时展示章节数、依据覆盖、待核对章节、缺失项和各章字数；
5. 用户确认正文后，才可导出 Word `.doc` 或 Markdown `.md`；
6. 报告保存至首页“我的写作”，可再次打开。已确认或已导出的正文再次编辑后会回到“正文待确认”。

客户端只把当前一篇文献的题录、摘要和本次解读设置发送至模型，不发送整个检索批次。题名、作者、期刊、年份、PMID 和 DOI 使用文献事实源的快照，模型不能修改。服务端固定章节顺序，强制校验 `evidenceText` 必须是题名或摘要中的连续原文；无法验证的事实型章节会变为“未从当前可用内容获得”。当前 Demo 未获取或解析全文，因此报告固定标记为“摘要级解读”，未提供的方法、统计结果和研究局限不得由模型补写。

任务、文献快照、生成结果、用户编辑、确认时间和导出记录保存在浏览器 `localStorage`。生成时直接刷新页面会把任务恢复为可重试的“生成失败”，并保留文献快照和解读设置。未配置模型或模型调用失败时，使用同一事实边界下的规则回退，并在报告中标记“演示回退”。

## PubMed 文献检索

“补充医学依据”已接入 PubMed E-utilities：

- 模型根据病例、大纲和汇报要求生成英文 PubMed 检索式；
- 服务端通过 `ESearch` 获取 PMID，再通过 `ESummary` 和 `EFetch` 获取真实题名、期刊、年份、作者、摘要、文献类型和 DOI；
- 模型只分析当前 PubMed 召回批次，不生成题录；
- 用户可以查看摘要和 PubMed 来源、选择或取消选择文献；
- 只有已选择的文献会进入 PPT 页面规划，且保留真实 PMID；
- PubMed 请求失败时显示失败原因，不使用模型生成的文献替代。

可选环境变量：

- `NCBI_API_KEY`：NCBI API Key；
- `NCBI_EMAIL`：调用方联系邮箱；
- `NCBI_TOOL`：调用方工具名称，默认 `clinpaper-case-ppt-demo`；
- `PUBMED_BASE_URL`：默认 `https://eutils.ncbi.nlm.nih.gov/entrez/eutils`；
- `PUBMED_TIMEOUT_MS`：默认 30 秒；
- `PUBMED_MAX_RESULTS`：单次最大召回数，默认 30，上限 100。

未配置 `NCBI_API_KEY` 时仍可检索，服务端会使用更严格的请求间隔。API Key 只在服务端使用，不发送到浏览器。

## 病例文件解析

用户点击“开始生成”或在步骤 1 点击“重新解析”时，前端会将真实文件上传到 `/api/case/materials`，而不是只提交文件名。服务端先提取文件文本，再把文件文本与用户补充文字一起交给 `parse_case` 模型结构化。

- `.docx`：使用 Mammoth 提取文本；
- `.pdf`：提取 PDF 文本层，纯扫描 PDF 会提示转为图片；
- `.jpg` / `.jpeg` / `.png` / `.webp`：使用同一组综述模型配置进行多模态文字识别，只提取可见内容；
- `.txt` / `.md` / `.csv`：按 UTF-8 文本提取，主要用于联调；
- `.doc`：旧版 Word 暂不支持，页面会提示另存为 `.docx`。

一次最多上传 10 个文件，单文件最大 30 MB；图片文字识别单文件最大 10 MB。浏览器刷新后不保留本地 `File` 对象，因此不会显示无法再解析的旧文件名，需要时请重新选择文件。

## 任务数据流转

- 开始新病例或重新解析病例时，会清空旧任务的时间线、主线、大纲、医学依据和 PPT 页面，避免不同病例串线。
- 时间线事件类型只能使用页面已定义的类型；“病例原文”保留支持当前事件的原文摘录，无缺失内容时不显示“必须补充”。
- 已确认的病例分组和时间线作为事实源，同时传入大纲、医学依据和逐页规划；已提供的日期、数值、药物剂量和随访不得在后续阶段降级为“待核对”。
- 汇报主线优先满足用户的补充说明；最高匹配方案排在第一项，且只保留一个“推荐”状态。
- 在“核对病例资料”点击下一步后，页面立即进入“梳理诊疗经过”，并在新页显示“正在生成诊疗时间线，通常需要 30–60 秒”；模型失败时返回病例核对页。
- “修改病例”可正常进入编辑状态。保存或新增资料后，页面显示明确的“需要重新解析”说明，重新解析完成后恢复下一步。

## 首页任务恢复

病例汇报 PPT 完成逐页规划并进入生成阶段后，会出现在 ClinPaper 综合首页“我的写作”区域。卡片显示任务类型、任务名称、最近生成日期和当前生成状态。

- PPT 构建元数据与最近生成时间保存在浏览器 `localStorage` 中；
- 点击卡片时会校验同源 SVG 预览文件是否仍然存在；
- 构建有效时直接恢复“生成并导出 PPT”页面；
- 服务重启导致临时构建文件失效时，恢复到“选择 PPT 模板”并提示重新生成；
- 恢复操作本身不会自动调用模型或重新生成 PPT；
- 编辑逐页内容、切换模板、更改比例或修改上游内容后，旧构建及生成时间会被清空。

## PPT 模板接入

“规划 PPT 页面”后新增“选择 PPT 模板”，完整流程为 9 步。

- 服务端根据 `ppt-master` 的 `layouts_index.json` 和 `decks_index.json` 读取已登记模板；
- 可通过 `PPT_MASTER_SKILL_ROOT` 覆盖 Skill 路径，默认使用 `/Users/dingxiangyuan/Downloads/ppt-master/skills/ppt-master`；
- 可通过 `PPT_MASTER_PYTHON` 指定具备 `ppt-master` 依赖的 Python 运行时；
- `GET /api/ppt/templates` 按 16:9/4:3 返回模板元数据；
- `GET /api/ppt/templates/preview` 返回 Skill 原始 SVG 封面预览；
- 当前 16:9 提供 `Report Core`、`Presentation Core`、`Editorial Bleed`、“中国电信”和“中汽研”，4:3 提供 `Presentation Core 4:3`；
- “规划 PPT 页面”中的每个非空内容行先锁定为稳定内容块 `s{slideIndex}-b{blockIndex}`，并提取日期、数值、单位、剂量和 PMID 等事实锁；
- `slides` 模型同时生成 `task_id`、`page_no` 和 `visual_spec`。页面角色与叙述、卡片、对比、时间线、数据、KPI、图表、表格、诊疗路径、医学依据、核心结论、图片等视觉类型分开表达；
- `visual_spec.items.source_refs` 只允许引用 `content:n` 原文行。服务端用引用行回填 `value/detail`、删除无效或重复引用并补齐遗漏行，防止视觉结构引入新病例事实；
- 规划页显示并允许修改视觉类型、条目标签和视觉语气，支持单独调用 `slide_visual` 模型重新分析当前页；
- 规划页支持为当前页上传 1 张 JPG、JPEG、PNG 图片，单张不超过 30 MB；重新上传会替换当前页图片。上传后展示缩略图、大小、用户图注、隐私提示和删除入口，并将当前页切换为图片视觉；
- 模板确认后，服务端调用 `ppt_design` 模型。模型只能从所选模板的真实 Layout 中返回 `layoutKey`，并通过 `placements[{blockId, slot}]` 把原文块放入 `subtitle`、`lead`、`body`、`item`、`timeline`、`left`、`right` 或 `reference` 槽位；模型不能返回或改写页面原文；
- 服务端过滤非法或重复的内容块 ID，并自动补回模型遗漏的内容块；
- 生成引擎根据 SVG Placeholder 的真实边界、字体和行高计算槽位容量。容量不足时先切换为更合适的 Layout，仍不足时生成“标题（续）”“标题（续2）”页面；能在新页完整放置的内容块不会被拆散，单个超长内容块才允许跨槽位或跨页拆分；
- 长标题优先切换到可完整容纳的 Layout；仍受版式限制时只调整标题字号，不修改标题文字；
- 主生成链路为 `规划 PPT 原文 → 内容块与事实锁定 → 模型选择 Layout、槽位和视觉载体 → 容量不足自动换版或续页 → 专用 Renderer 生成同源 SVG → 内容、事实、载体门禁 → ppt-master 最终质量门禁 → svg_to_pptx → PPTX postflight`；
- 内容覆盖门禁在最终用于编译的 `svg_output` 上检查每个标题、内容块和事实锁；任一内容被截断、遗漏或改变时阻止导出，不再使用省略号静默截断；同时增加 `visual_spec_coverage` 门禁，需要结构化视觉的原文块未被引用时阻止导出；
- 通过门禁后直接以同一份 `svg_output` 生成预览和 PPTX，Quick Generate 路径不再运行 `finalize_svg.py`；
- `POST /api/ppt/build` 返回生成 ID、同源 `svg_output` 预览、质量回执、Master/Layout/Notes 数量和下载地址；
- `POST /api/ppt/build` 同时返回内容覆盖率、规划内容块数量、事实锁命中数、实际视觉载体种类、卡片占比、自动续页数和容量换版数；临时项目只在 `validation/content_coverage_report.json` 保存计数，不保存病例原文；
- 输出为结构化 DrawingML PPTX，保留真实 Master、Layout、Placeholder、可编辑文本框和每页讲者备注；
- 导出页展示的最终 SVG 与 PPTX 使用同一份页面源，切换模板、调整比例或编辑页面后会使旧 build 失效；
- 原 `/api/pptx` PptxGenJS 简化路径仅作兼容回退，页面主流程不再调用该路径；
- 品牌 Deck 在页面中标记授权使用边界。

## PPT 版式多样性

`ppt_design` 不再只接收 Layout 名称。服务端同时提供页面意图、内容特征以及每个真实 Layout 的用途、槽位类型、文本槽位数量和媒体要求。

- 封面、目录、时间线、对比、数据、医学依据和总结页优先使用专用 Layout；
- 当前页面没有可用图片时，不选择依赖图片的 Layout；
- 同一 Layout 原则上不连续超过 2 页，通用 `title_content` / `content` 不应主导整套内容页；
- 模型仍返回单一版式时，引擎会按页面意图确定性重新规划；
- 标题容量不足时优先在同类 Layout 中换版；
- 续页从同类 Layout 变体中按剩余内容容量选择，不再固定使用 `title_content`；
- 5 页及以上的结构化 Layout 模板启用版式多样性门禁，检查 Layout 种类、主导占比和连续重复；
- 第一次检查未通过时自动强化重规划，仍不通过则阻止导出；
- 导出回执展示 Layout 种类、主导占比、自动重规划、容量换版和续页数量。

## PPT 视觉载体

Layout 只负责模板 Master、Layout、标题、页眉和页脚；内容区按 `visual_spec.type` 使用独立的原生 SVG Renderer，不再统一转成卡片。

- 普通内容默认使用 `narrative` 的强调线、核心句和分层正文；
- `timeline` 绘制真实时间轴与节点，`algorithm` 绘制诊疗节点、连接线和箭头；
- `comparison` 使用左右分栏和中轴，`table` 使用真实表格网格；
- `data`、`kpi`、`chart` 使用指标与图形，完整规划原文仍保留在页面；
- `evidence` 分开呈现病例事实和外部医学依据；
- `statement` 使用大字号结论表达；
- `image` 使用当前页真实上传图片、用户图注和已锁定原文生成图文页；图片二进制不发送给 Layout 策略模型；
- `cards` 仅用于 2–4 个并列同权重内容，5 个及以上内容页时最多占 40%，且不连续超过 2 页。

每个内容页 SVG 声明 `data-clinpaper-carrier`。`carrier_semantics` 检查载体所需原生结构，`carrier_diversity` 检查规划载体与实际载体一致、卡片占比和连续卡片页数；任一检查失败都会阻止导出。导出回执显示实际载体种类和卡片占比。

页面图片只保存在当前浏览器页面内存和本次生成请求中，不写入 `localStorage`，刷新后需要重新上传。当前 Demo 只提供隐私提示，未自动识别或遮挡姓名、住院号、检查号等身份信息，用户需要在上传前完成脱敏。
